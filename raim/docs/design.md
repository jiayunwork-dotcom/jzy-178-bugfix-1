# 设计说明：单历元算法与跨历元状态管理

## 1. 单历元层（与上一版一致）

### 1.1 加权单点最小二乘定位

观测模型（线性化于当前估计位置）：

```
y = G·dx + ε,   G 每行 = [-ux -uy -uz 1]
W = diag(1/σ_i²)
dx = (GᵀWG)^{-1} GᵀW y
```

- 初值取概略位置（回放时沿用上一历元定位结果，首历元用输入或卫星反推的地表点）；
- 收敛判据：位置修正 ‖Δxyz‖ < 1 mm，或迭代 10 轮；
- 输出 ECEF 与经纬度高（WGS84 Bowring 闭式迭代）、钟差、实际迭代轮数、每星残差。

### 1.2 检测

加权残差平方和

```
SSE = Σ_i (r_i / σ_i)²   ~ χ²(n−4)  (H0 无故障)
```

阈值 `T` 满足 `P(χ²(n−4) > T) = Pfa`（卡方分位数由 `pkg/chisq` 反解，自研）。

- n < 5：只有定位、无冗余，结果标 `unavailable`（完好性不可用）；
- n ≥ 5 且 SSE ≤ T：`ok`；
- SSE > T：检出故障。

### 1.3 排除

- n < 6：剔后只剩 4 颗无冗余再检，**只能检出、无法排除**，报 `detected`；
- 否则逐星剔除重解，对 n−1 颗星的子集重算 SSE 与对应自由度（n−5）的阈值；
- **恰有一颗**星剔后通过检验，才认为故障可唯一解释，报 `excluded` 并采用剔星后的干净解；
- 没有任何剔法通过（疑似多星故障），或多颗星剔后都通过（无法唯一识别），都按 `detected`
  处理，不使用任何剔星解。

### 1.4 水平保护级 HPL

Brown/Sturza 斜率法：

```
HPL = slopeMax · √λ
```

- `slope_i = ‖(A 前两行)[:,i]‖·σ_i / √S_ii`，A=(GᵀWG)⁻¹GᵀW，取最大斜率；
- √λ 满足 `P(χ'²(dof, λ²) ≤ T) = Pmd`，对非中心卡方 CDF 反解非中心参数（自研）；
- 排除成功后用剩余星几何与 n−5 自由度。几何越差（斜率越大）HPL 越大。

## 2. 跨历元状态管理（本版新增）

### 2.1 隔离 / 恢复

某历元被唯一排除的星进入隔离集合。之后每个历元：

- 隔离星**不参与**定位解；
- 但仍逐历元对它做恢复检验，检验基于**本历元实际采用的、不含任何隔离星的
  干净基础解**（单历元层的全解或唯一排除解）：
  1. **单星新息检验（选型见 2.1.2）**：在不含该星的基础解上预测它的伪距，
     新息 `innov = PR − (range + 钟差)` 按其理论标准差归一化为
     `d = innov/σ_innov`，要求 `|d| ≤ √T`（门限取加回后整体卡方门限的平方根，
     与整体检验一致的保守判据）；
  2. **加回后整体检验**：把该星加回基础解后的整体加权 SSE 由加权 SSE 增量
     恒等式直接给出，`SSE_full = SSE_base + d²`（不必重解），要求
     `SSE_full ≤ T`，自由度为基础星数−3。
- 上述两条件须**连续**满足 `isolation.min_epochs` 个历元才解除隔离；
- 期间任一历元不满足（含基础解不可解/冗余不足的“不可评估”情形），或该星
  本历元不可见，计数清零重新累计。

**为什么不能用“含所有隔离星的全星解”做检验**：双星先后故障时，后故障的星会
污染全星解，先故障、其实已恢复的星每一历元都因整体 SSE 被别人的大偏差顶高而
无法累计恢复计数，表现为“一旦有第二颗星进隔离，先恢复的星永远出不来”，解算
星数与 HPL 一直停在双星缺失的水平（试飞组回放所见）。本版基础解排除了全部隔离
星，各隔离星的检验彼此独立：别的星（包括同时隔离的坏星）的残差**无法替它掩护**，
它若仍带大偏差，`|d|` 会直接暴露。

解除隔离发生在该历元解算之后，因此该星在“解除”的下一历元才重新参与解算——
这保证“同一历元用排除解、又把同一颗星当正常”不会发生。回放验证（9 星、ts9–ts16 注入
80 m 偏差）：ts9 排除后 ts10–ts20 始终隔离、绝不回拉，偏差撤掉后连续 5 个正常历元，ts21
恢复，故障期间定位始终贴近真值。双星回放（10 星、σ=1 m、min_epochs=4）：PRN3 在
ts5–ts10 加 80 m、PRN6 自 ts8 起一直加 80 m，PRN3 偏差 ts11 撤除后 ts11–ts13 连续
3 个正常历元、**ts14 解除**（与 PRN6 是否同时隔离无关），PRN6 因偏差仍在而始终
隔离；把 PRN6 起点挪到 ts12（PRN3 正攒恢复计数）时，ts12 唯一剔除 PRN6 不会清零
PRN3 已攒下的计数，PRN3 同样在 ts14 解除；两颗偏差都撤掉后两颗都能回到解算。

#### 2.1.1 多颗星同一历元同时满足恢复条件：选型

**本版选择：一起放回。** 各隔离星的恢复检验基于同一干净基础解独立进行，谁先
攒够 `min_epochs` 谁在该历元解除；同一历元多颗星都攒够时一并解除，它们都在
下一历元才参与解算，不做“放回一颗后当历元重新整体复核”。

| 维度 | 一起放回（本版） | 一次一颗、放回后整体复核（备选） |
|---|---|---|
| 可用率 | **更高**：多颗星可在同一历元恢复，冗余/HPL 一次回到正常水平；不存在“另一颗已恢复却还要多等若干历元”的损耗 | 更低：每次只回一颗且还要再复核，N 颗恢复要串行占用约 N 个历元窗口 |
| 恢复延迟 | **更短**：延迟只取决于各自偏差撤除时刻 + min_epochs，互不拖延 | 更长：后放回的星被排在队列后面，即使早已正常也要等前面的星复核完 |
| 坏星误放回风险 | 略高：两星恢复判断共享同一历元的几何/噪声实现，若异常恰好在同历元相关（如共模故障），可能双双过关——但这已超出单星故障假设；且二者都已连续 min_epochs 通过各自独立的新息检验，风险受双重门限限制 | **更低**：每放回一颗都在含该星的解上整体复核，能顺带发现“单看正常、合在一起相互配合”的相关/共模异常，是对多星相关故障更保守的姿态 |

单星 RAIM 的故障假设本就是“同一时刻至多一颗故障星”；双星场景里两颗只是先后被
隔离，恢复期共模概率低，而串行复核要持续牺牲可用率与恢复延迟，故内置实现选
一起放回。对共模多星故障高度敏感的监测可改用一次一颗 + 整体复核，代价是恢复
期再长若干历元、可用率略低。

#### 2.1.2 单星“正常”怎么判定：选型

**本版选择：在不含该星的解上做预测再比（外推新息检验）。** 用干净基础解
（其余活动星）预测候选星伪距，拿预测残差（新息）与其理论标准差比，而不是把该星
放进解之后看它自己的定位后残差。加权 SSE 增量恒等式 `SSE_full = SSE_base + d²`
让“加回后整体检验”不用重解即可精确得到。

| 维度 | 不含它的解上预测再比（本版） | 放进解里再看本星后验残差（备选） |
|---|---|---|
| 可用率 | 略低（影响很小）：新息门限对“边界上可接受”的星略严，边界星恢复可能多等一两个历元 | **略高**：后验残差是解算拟合的一部分，小偏差会被吸收一部分，边界星更容易过关、恢复更早 |
| 恢复延迟 | 干净星相同（噪声下两者都轻松过门限）；临界正常星可能**略长** | 干净星相同；临界星**略短** |
| 坏星误放回风险 | **更低**：候选星不影响基础解，80 m 这类残余偏差在新息里几乎原量级暴露（`|d|` 数十），且别的星的残差无法替它吸收——双星场景下“被另一颗坏星掩护”的路径从定义上就不存在 | 更高：后验残差被最小二乘按几何斜率吸收，偏差越能转化为位置/钟差误差，自残差越不明显；多个隔离星一起进解时，异常还会在星间分摊，极端情况下两颗星互相“掩护” |

备选方案（含该星重解取后验残差）只在边界星的恢复延迟/可用率上略好，本版用新息
检验换取对残余偏差（尤其多星隔离叠加时）显著更高的拒识能力，与 RAIM “安全优先”
一致；代价仅是临界正常星偶发的一两个历元延迟，以及一次基础解上的轻量计算。

#### 2.1.3 逐历元隔离检验输出

每个历元结果里，对每颗“本历元可见且处于隔离”的星（含本历元刚被唯一排除的星）
输出一行 `isolation_tests`：

| 字段 | 含义 |
|---|---|
| `statistic` | 单星检验统计量 `|d|`（干净基础解上的标准化新息） |
| `threshold` | 单星门限 `√T` |
| `sat_pass` | 本星新息检验是否过门限 |
| `full_sse` / `full_threshold` / `full_pass` | 加回后的整体 SSE（SSE 增量恒等式）、整体门限、是否通过 |
| `pass` | 综合判定（两者皆过）；不可评估时为 false |
| `normal_streak` | 本历元之后已连续正常的历元数（攒够 min_epochs 即解除） |
| `evaluable` | 本历元是否成功完成检验（基础解不可解/冗余不足为 false，统计量与门限记 0、计数清零） |

刚解除隔离的星不出现在该历元明细中（下一历元即作为正常星回到 `sat_results`）。
该输出同样满足：整段批量与逐历元提交逐项相等，中途重启续跑与一口气跑完相等。

### 2.2 告警判定：选型

告警条件是“检测失败（检出无法排除 / HPL > HAL）”。注意：**成功排除单星后采用干净解，
不再告警**——这是上一版“告警跟着坏星反复进出而闪烁”的根因之一；真正需要告警的是
无法安全解释的风险。

三种判定方式（运行档 `alert.mode` 可选）：

1. **逐历元快照 `snapshot`**：一个历元超限立即告警，下一历元正常立即撤警。
   - 优点：首次告警延迟最短；缺点：单历元残差尖峰直接变成闪烁告警，误警最多。

2. **持续性窗口 `persistence`**：连续 `confirm_epochs` 个历元超限才拉起，
   连续 `clear_epochs` 个正常才撤除；窗口内一次反复会打断计数。
   - 优点：尖峰被滤掉、误警最少；缺点：真实故障的首次告警最多滞后 `confirm_epochs` 个历元。

3. **组合 `combined`（默认，内置三档均采用）**：普通超限走持续性窗口；
   **恶劣超限**（SSE ≥ `gross_factor×T` 或 HPL ≥ `gross_factor×HAL`）立即告警，
   撤警仍走窗口。
   - 既对“明显危险”保持即时响应，又对“边界附近的抖动”保持迟滞。

> 结论：三者不是互斥替代，而是**延迟—误警—可用率**的权衡。内置档选 `combined`，
> 把“立即响应恶劣故障”和“滤掉边界闪烁”同时拿到；对延迟极度敏感的阶段可下调
> `confirm_epochs` 或改用 `snapshot`，对误警极度敏感的监测可只用 `persistence`。

\* 组合模式在恶劣故障上当历元即告警，因此比“等满 3 历元”的持续性方式多覆盖了故障开头
2 个历元的告警（更保守），可用率略低但响应更及时。

读数：

- **首次告警延迟**：快照恒为 1；持续性对中等故障需等满窗口（本例 6，因噪声使前两个超限
  历元未连续）；组合对**恶劣**故障回到 1，对中等故障与持续性一致（有意迟滞）。
- **误警次数**：快照在纯噪声/尖峰下分别产生 3、4 个误警片段（正是试飞组看到的闪烁），
  持续性与组合为 0。
- **可用率**：持续性/组合在无故障与尖峰场景保持 100%；快照因误警受损。真实故障期间
  告警越保守可用率越低，这是为安全付出的代价；组合在“恶劣故障即时告警”和“其余时间
  高可用”之间取得平衡。

### 2.4 误警口径

- 在线服务（`session.Stats.FalseAlarms`，无地面真值）：一个告警片段内**从未识别出任何
  故障**（无检测/排除事件）才算误警——这是接收机自身能做的保守统计。
- 回放分析（`replaydemo`，知道注入真值）：告警片段与“真实持续故障窗口”不相交才算误警。
  单历元尖峰触发的快照告警因此被正确标为误警。

## 3. 会话与持久化

- 会话创建时绑定一个运行档；可一次批量提交（≤3600 历元，整段原子、任一历元非法整段拒收），
  也可逐历元提交；两条路径调用**同一个 `Service.Step`**，逐历元结果严格一致。
- 时间戳：与上一历元相同 → 409 拒收、状态不推进；倒退 → 422 拒收。
- 状态（隔离集合及计数、告警机、统计、last_ts、全部记录）以 JSON 原子写
  （临时文件 + rename）落盘；重启后从最后历元继续，与一口气跑完逐项相等。
- 每个历元记录都带所用档名、Pfa/Pmd/HAL、当时卡方阈值与自由度。
- **升级兼容（仅追加字段）**：新输出字段 `isolation_tests` 为 JSON 可选追加字段
  （`omitempty`），状态结构未变。升级前写出的会话可直接加载续跑；已有历史记录
  原样保留、不回填不改写，新历元起才带新字段。隔离中的旧会话加载后，其
  `normal_streak` 计数与 `since_epoch_seq` 均沿用，恢复时序不因升级中断或重置。

## 4. 输入校验（错误指到具体字段）

不足 4 颗星、卫星编号重复、坐标/伪距 NaN 或无穷、σ≤0、概略位置近地心、卫星共面等几何
奇异，分别返回带字段路径的错误（如 `epochs[3].satellites[1].sigma`）。
