# 设计说明：单历元算法与跨历元状态管理

## 1. 单历元层（与上一版一致）

### 1.1 加权单点最小二乘定位

观测模型（线性化于当前估计位置）：

```
y = G·dx + ε,   G 每行 = [-ux -uy -uz 1]
W = diag(1/σ_i²)
dx = (GᵀWG)^{-1} GᵀW y
```

- 初值取概略位置（回放时沿用上一历元定位结果，首历元用输入或卫星反推的地表点）；
- 收敛判据：位置修正 ‖Δxyz‖ < 1 mm，或迭代 10 轮；
- 输出 ECEF 与经纬度高（WGS84 Bowring 闭式迭代）、钟差、实际迭代轮数、每星残差。

### 1.2 检测

加权残差平方和

```
SSE = Σ_i (r_i / σ_i)²   ~ χ²(n−4)  (H0 无故障)
```

阈值 `T` 满足 `P(χ²(n−4) > T) = Pfa`（卡方分位数由 `pkg/chisq` 反解，自研）。

- n < 5：只有定位、无冗余，结果标 `unavailable`（完好性不可用）；
- n ≥ 5 且 SSE ≤ T：`ok`；
- SSE > T：检出故障。

### 1.3 排除

- n < 6：剔后只剩 4 颗无冗余再检，**只能检出、无法排除**，报 `detected`；
- 否则逐星剔除重解，对 n−1 颗星的子集重算 SSE 与对应自由度（n−5）的阈值；
- **恰有一颗**星剔后通过检验，才认为故障可唯一解释，报 `excluded` 并采用剔星后的干净解；
- 没有任何剔法通过（疑似多星故障），或多颗星剔后都通过（无法唯一识别），都按 `detected`
  处理，不使用任何剔星解。

### 1.4 水平保护级 HPL

Brown/Sturza 斜率法：

```
HPL = slopeMax · √λ
```

- `slope_i = ‖(A 前两行)[:,i]‖·σ_i / √S_ii`，A=(GᵀWG)⁻¹GᵀW，取最大斜率；
- √λ 满足 `P(χ'²(dof, λ²) ≤ T) = Pmd`，对非中心卡方 CDF 反解非中心参数（自研）；
- 排除成功后用剩余星几何与 n−5 自由度。几何越差（斜率越大）HPL 越大。

## 2. 跨历元状态管理（本版新增）

### 2.1 隔离 / 恢复

某历元被唯一排除的星进入隔离集合。之后每个历元：

- 隔离星**不参与**定位解（本历元的定位、SSE、HPL 均在不含隔离星的活动集上算）；
- 但仍逐历元对每颗可见隔离星单独计算恢复检验量（见 2.1.1）；
- 检验连续通过 `isolation.min_epochs` 个历元才具备放回资格；放回按
  2.1.2 的“逐个放回、放回后整体复核”策略执行；
- 期间任一历元不通过，或该星本历元不可见，计数清零重新累计。
- **别的星被新排除不会清零本星计数**：一颗星的恢复评估只在“不含它自己、
  也不含其他隔离星”的干净基线上进行，其他隔离星（含刚被剔除的星）的
  残差既不进入它的解，也不参与它的检验。

解除隔离发生在该历元解算之后，因此该星在“解除”的下一历元才重新参与解算——
这保证“同一历元用排除解、又把同一颗星当正常”不会发生。

#### 2.1.1 单星恢复检验（留一解上的预测检验）

评估隔离星 *k* 时，基线解只用“可见且未隔离”的星（既不含 *k*，也不含其他
隔离星），得到基线位置与钟差。在该位置上形成 *k* 的视线行
`g_k=[-ux -uy -uz 1]`，计算：

```
δ_k   = PR_k − (几何距离 + 基线钟差)                      （留一预测残差，米）
v_k   = σ_k² + g_kᵀ (GᵀWG)^{-1} g_k                       （预测误差方差，米²）
z_k   = δ_k / √v_k                                        （单星检验量，H0 下 N(0,1)）
T     = χ²_{n−4, 1−Pfa}
```

两个条件同时满足才算一个恢复历元：

1. 单星检验 `|z_k| ≤ √T`；
2. 加回后整体检验：加权最小二乘的恒等式给出
   `SSE_add = SSE_base + z_k² ≤ T`（与重解一次“基线 +k”的加回解完全等价，
   无需重复最小二乘；自由度 n−4）。

> 历史缺陷（双星隔离时好星永久卡死的根因）：旧实现让**所有**隔离星共用
> 同一个“含全部星的全解”，各自只看自己在该解里的拟合残差。只要还有一颗
> 隔离星带着大偏差，这个共用解就被它拉偏，其余已恢复星的“加回整体检验”
> 每个历元都失败、计数反复清零，于是再也出不来；且坏星之间等于在互相
> 掩护。改成“每颗星一个独立干净基线 + 留一预测”后，别的隔离星的残差
> 无法再影响本星的检验量与计数。

为什么用“不含它的解做预测再比”，而不是“把它放进解里看拟合残差”（本实现
的选型，两种做法的对比见 2.1.3）：拟合残差经过投影矩阵 `S=I−G(GᵀWG)^{-1}GᵀW`，
一颗带偏差的星会把解往自己方向拉，从而**吸收掉自己的大部分偏差**，其标准化
拟合残差被系统性缩小（漏检方向偏乐观）；留一预测残差不允许该星参与拟合，
偏差无法被吸收，检验量在 H0 下恰好服从 N(0,1)，对“坏星是否已恢复”是更直接、
更不偏袒的检验。

每个历元的记录里，每颗可见隔离星都带：`test_stat`（|z|）、`self_threshold`
（√T）、`add_sse`、`add_threshold`、`passed`、`normal_streak`；本历元新被
唯一排除的星同样输出（streak=0），本历元决定放回的星保留其放回前最后一次
检验（streak 已达标）。这样回放时可以直接看到每颗隔离星“为什么出不来”。

#### 2.1.2 多颗隔离星同时攒满历时的放回策略

**选型：一次只放一颗，放回后对其余候选在扩大后的基线上整体复核。**

同一历元可能有几颗星都攒满了恢复历元。处理次序：

1. 取当前攒满的候选集合，把其中“本历元检验量 |z| 最小（最正常）”的一颗放回；
2. 基线扩大一颗，对其余候选重新做 2.1.1 的两项检验；
3. 仍通过者保留资格，任一不过者本历元不放回、计数清零；
4. 重复 1–3，直到没有候选。

另一种方案是**同历元一起放回、不做联合复核**。两者权衡：

| 维度 | 逐个放回 + 联合复核（选用） | 同历元一起放回 |
|---|---|---|
| 可用率 | 略低：联合复核不过的候选要再攒满一个计数周期，回解晚若干历元 | 略高：攒满即回解，恢复最快 |
| 恢复延迟 | 多颗候选时，后面的星最多多等一个复核轮次（通常仍在同历元内完成） | 最短，无额外延迟 |
| 把坏星误放回来的风险 | **低**：单星留一检验各自通过、但只有合在一起才暴露的“共谋”组合，会在放回后的联合检验中被拦下（见下注） | 高：各自干净、合起来超门限的组合会被同批放进解，下一历元只能靠常规检测兜底 |

> 注：留一基线同样不含其他隔离星，所以“各自检验”本身已经排除了坏星互相
> 拉偏的问题；联合复核是第二道防线，针对的是单颗偏差都低于单星门限、但
> 两颗叠加后整体 SSE 超门限的组合故障。顺序选择 |z| 最小者先放，保证次序
> 确定、可复现（不依赖 map 遍历），且最可能正常的星先扩大基线。

#### 2.1.3 单星正常性的残差口径

**选型：在不含该星的基线解上做预测，再与它的观测比较（留一预测残差）。**

另一种方案是**把该星放进解后取它的拟合残差**。两者权衡：

| 维度 | 留一预测残差（选用） | 含星拟合残差 |
|---|---|---|
| 可用率 | 略低：检验更“敏感”，临界恢复的星可能多等一两个历元 | 略高：拟合残差偏小，星更容易被判正常、回解更早 |
| 恢复延迟 | 略长（同上，量级通常 1–2 个历元） | 略短 |
| 把坏星误放回来的风险 | **低**：偏差无法被自己拉偏的解吸收，检验量在 H0 下精确服从 N(0,1)，门限 √T 与整体卡方口径一致 | 高：投影矩阵吸收偏差，标准化拟合残差系统性偏小；偏差越大、几何越好（该星权重越高）吸收越明显，容易把仍带偏差的星判成正常 |
| 计算量 | 每颗隔离星一次干净基线解 | 可与全解共用，计算略省 |

结论：恢复判据是安全攸关环节，选用不漏检的留一预测口径，用少量恢复延迟
换更低的误放回风险；对延迟更敏感的阶段可下调 `isolation.min_epochs`，
而不是放松单星口径。

回放验证：

- 单星场景（9 星、ts9–ts16 注入 80 m 偏差）：ts9 排除后始终隔离、绝不回拉，
  偏差撤掉后连续 5 个正常历元恢复，故障期间定位始终贴近真值；各历元编号与
  旧版完全一致（既有测试逐历元断言保持不变）。
- 双星场景（10 星、σ=1 m、min_epochs=4）：PRN3 第 5–10 历元、PRN6 第 8 历元
  起均加 80 m 偏差。第 5 历元剔 PRN3、第 8 历元剔 PRN6；PRN3 偏差撤掉后
  第 11–13 历元 streak=1/2/3，**第 14 历元解除**、第 15 历元回解；PRN6 偏差
  持续期间始终隔离，其偏差不影响 PRN3 的计数；两星偏差都撤后两星均回解。
  PRN6 改为第 12 历元才开始加偏差时（PRN3 正攒计数），PRN3 同样在第 14 历元
  解除——第 12 历元 PRN6 被剔不清零 PRN3 已攒的计数。

### 2.2 告警判定：选型

告警条件是“检测失败（检出无法排除 / HPL > HAL）”。注意：**成功排除单星后采用干净解，
不再告警**——这是上一版“告警跟着坏星反复进出而闪烁”的根因之一；真正需要告警的是
无法安全解释的风险。

三种判定方式（运行档 `alert.mode` 可选）：

1. **逐历元快照 `snapshot`**：一个历元超限立即告警，下一历元正常立即撤警。
   - 优点：首次告警延迟最短；缺点：单历元残差尖峰直接变成闪烁告警，误警最多。

2. **持续性窗口 `persistence`**：连续 `confirm_epochs` 个历元超限才拉起，
   连续 `clear_epochs` 个正常才撤除；窗口内一次反复会打断计数。
   - 优点：尖峰被滤掉、误警最少；缺点：真实故障的首次告警最多滞后 `confirm_epochs` 个历元。

3. **组合 `combined`（默认，内置三档均采用）**：普通超限走持续性窗口；
   **恶劣超限**（SSE ≥ `gross_factor×T` 或 HPL ≥ `gross_factor×HAL`）立即告警，
   撤警仍走窗口。
   - 既对“明显危险”保持即时响应，又对“边界附近的抖动”保持迟滞。

> 结论：三者不是互斥替代，而是**延迟—误警—可用率**的权衡。内置档选 `combined`，
> 把“立即响应恶劣故障”和“滤掉边界闪烁”同时拿到；对延迟极度敏感的阶段可下调
> `confirm_epochs` 或改用 `snapshot`，对误警极度敏感的监测可只用 `persistence`。

读数：

- **首次告警延迟**：快照恒为 1；持续性对中等故障需等满窗口（本例 6，因噪声使前两个超限
  历元未连续）；组合对**恶劣**故障回到 1，对中等故障与持续性一致（有意迟滞）。
- **误警次数**：快照在纯噪声/尖峰下分别产生 3、4 个误警片段（正是试飞组看到的闪烁），
  持续性与组合为 0。
- **可用率**：持续性/组合在无故障与尖峰场景保持 100%；快照因误警受损。真实故障期间
  告警越保守可用率越低，这是为安全付出的代价；组合在“恶劣故障即时告警”和“其余时间
  高可用”之间取得平衡。

### 2.4 误警口径

- 在线服务（`session.Stats.FalseAlarms`，无地面真值）：一个告警片段内**从未识别出任何
  故障**（无检测/排除事件）才算误警——这是接收机自身能做的保守统计。
- 回放分析（`replaydemo`，知道注入真值）：告警片段与“真实持续故障窗口”不相交才算误警。
  单历元尖峰触发的快照告警因此被正确标为误警。

## 3. 会话与持久化

- 会话创建时绑定一个运行档；可一次批量提交（≤3600 历元，整段原子、任一历元非法整段拒收），
  也可逐历元提交；两条路径调用**同一个 `Service.Step`**，逐历元结果严格一致。
- 时间戳：与上一历元相同 → 409 拒收、状态不推进；倒退 → 422 拒收。
- 状态（隔离集合及计数、告警机、统计、last_ts、全部记录）以 JSON 原子写
  （临时文件 + rename）落盘；重启后从最后历元继续，与一口气跑完逐项相等。
- 每个历元记录都带所用档名、Pfa/Pmd/HAL、当时卡方阈值与自由度。
- **升级兼容**：持久化结构只新增字段（`isolation_checks` 为 omitempty），
  升级前写出的、其中正有星处于隔离的会话文件可直接加载续提；旧记录原样
  保留、不回填不改写，仅新历元携带新输出。

## 4. 输入校验（错误指到具体字段）

不足 4 颗星、卫星编号重复、坐标/伪距 NaN 或无穷、σ≤0、概略位置近地心、卫星共面等几何
奇异，分别返回带字段路径的错误（如 `epochs[3].satellites[1].sigma`）。
